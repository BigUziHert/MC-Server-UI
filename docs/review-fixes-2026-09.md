## Upgrade and API behavior

Existing remote cookie sessions require one new sign-in after upgrading. Accounts, passwords, server grants and invitation records remain. New remote sign-ins persist per origin and remain independent across different HTTPS ports. Browser origin storage is readable by scripts on that origin, so the application's existing script/content-security boundaries remain important.

New frontend clients supply operation IDs for destructive installation/restore confirmations and revisions for settings/schedule saves. Legacy API requests without these fields remain accepted for compatibility; external API clients must adopt the same fields to obtain retry and conflict protection. Explicitly closing and reviewing a new destructive operation creates a new ID. Accepted receipts survive history dismissal and host restart; an interrupted or unreadable receipt requires inspecting the server and reviewing a new operation, rather than automatically replaying a possibly committed action.

Properties drafts are intentionally in memory for the current sign-in. They survive page and server navigation within that workspace; they are discarded after confirmed sign-out, session expiry or closing the application. Full unload warns about outstanding drafts. An involuntary authentication expiry does not retain private drafts for the next account.

## Validation

- TypeScript and the Vite production build pass. Vite retains the existing bundle-size advisory.
- The full Node backend/desktop suite passes: 1,060 passed, one existing Windows symlink-privilege skip. The final Windows bundled-executable restore cases also pass in a focused rerun.
- The full browser run exercised 318 cases. Changed expectations for private recovery state, minimal settings patches and update wording were corrected. Final targeted runs cover 107 affected/new cases, including missing-file drafts, delayed saves, delayed authorization errors, real independent HTTPS origins, streamed download bytes and session persistence.
- Native connection, five-process saved-session persistence, remote frontend and menu smokes pass. Frontend and menu smokes were rerun against the final build.
- The `dev` GitHub workflow reruns the complete final suites, builds and tests the packaged Windows app, then publishes the tested development artifacts. See the associated commit's Actions run for final packaging results.

No production server data was used. Physical multi-computer/WAN behavior, real updater installation and privileged filesystem race/crash scenarios still require the separate environmental validation recorded in the review; these fixes do not imply those scenarios were exercised locally.
